# Prompt files

Use one workflow-owned `prompts/*.txt` file per distinct child task. A self-contained task supplies everything its active branch needs, not every fact available to the workflow.

## Build the task hierarchy

Write the task in this order, omitting sections that have no content:

1. **Goal and boundary:** exact outcome, included scope, priorities, and preserved invariants.
2. **Read first:** authoritative paths and what the child must learn from each.
3. **Work:** required actions in order, with branch-specific constraints.
4. **Inputs:** prior results or artifact paths and their required use.
5. **Deliver:** exact value or artifact, format, and path.
6. **Done when:** checkable evidence covering every required action and deliverable.
7. **Blockers:** conditions that require a blocker report instead of inference.

Keep universal steps in the task. Disclose branch-only reference through a sharp path pointer that names when to read it and what authority it carries. Co-locate each rule with its relevant step; split a prompt when distinct branches would otherwise compete for attention.

## Shape cacheable context

Put stable, branch-relevant instructions that are expensive to rediscover in the **static prefix**. Put per-launch paths, IDs, counts, manifests, and prior artifact references in a typed **dynamic suffix**. Matching launches should share the exact static prefix.

The environment is the source of truth for cheap lookups such as scripts, config values, directory layout, and `--help` output. Point to those sources instead of caching their contents in every prompt. Pass paths or compact manifests instead of copied project files and large prior results.

Launch with `agent({ template, values }, options)`. Every `{{name}}` must receive one value, and every supplied value must be referenced. Keep placeholders in the dynamic suffix where possible. Use `renderPrompt(...)` only for exceptional composition and inline text only for tiny one-off glue.

Pi-workflow owns `<workflow_instructions>`, `<workflow_task>`, `<workflow_context>`, and `<structured_output_contract>`; child prompt files use Markdown or plain text and leave those delimiters to the runtime. Load `structured-outputs` when the task returns machine-readable fields.
