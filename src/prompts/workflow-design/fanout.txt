# Fan-out

- Select the exact bounded input set before fan-out; never map an unbounded project tree.
- Use `parallel(items, worker, { label })` only when every selected item is independent. State the worker's identical task contract and the reducer's required use of each worker result.
- Use `pipeline(items, stages)` when every selected item must complete the same ordered stages.
- `mapreduce` applies its `extensions` and `tools` selection to input selection, every map worker, and reduction. `verifier` applies its selection to every voter and reduction. Set or intentionally inherit this authority explicitly.
- Record exact skipped scope with `log(...)` or `trace(...)` so users can see which inputs were intentionally excluded and why.
- Workflow runs obey the project `maxParallelAgents` cap. Design fan-out as a bounded queue, not an unbounded launch burst.
