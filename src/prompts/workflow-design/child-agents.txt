# Child agents

Load `prompt-files` first. Give each child one branch-complete task; the runtime wrapper supplies provenance, not missing task requirements.

- Pass authoritative paths and state what to learn from them. Let the child read source, config, and command help from the environment instead of pasting cached copies.
- Pass only prior values the branch consumes. Prefer artifact paths, IDs, counts, and compact manifests to bulk content.
- Set `taskFile` for the primary file and `cwd` for an alternate working directory. State any alternate read/write base in the task itself.
- Select `extensions` and `tools` intentionally. Omission inherits workflow settings, `[]` grants none, and a call-level list replaces its default. Tool lists are exact; a schema-enabled agent still receives `StructuredOutput`.
- Return compact downstream control data and write large outputs to named artifacts.
- Use `log(...)` around slow launches and handoffs; use `trace(...)` for compact debug state such as selected IDs and artifact paths.

The task is complete only when its stated deliverable exists and every completion check has evidence. A role label does not supply a task contract.
