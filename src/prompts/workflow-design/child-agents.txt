# Child agents

Give every child one explicit job. **State the exact outcome rather than expecting the child to infer it.** Each task packet must identify its goal and boundary, authoritative reads, required work, inputs, deliverable, completion evidence, and blockers. Follow the detailed packet rules in `prompt-files` before writing or changing a child prompt.

- Name every source-of-truth path and what the child must learn from it. Tell the child to read those paths with tools; do not paste large project files when a path gives the same evidence.
- State ordered actions, constraints, preserved invariants, edge cases, and priorities directly. A role name such as “reviewer” or “expert” is never a substitute for requirements.
- State the exact artifact path or structured fields to produce, including the evidence each result must contain.
- Pass every prior result the stage needs, with an explicit explanation of how to use it. Pass paths, IDs, counts, compact manifests, and evidence paths instead of repeated bulk content.
- Use `taskFile` for the primary file and `cwd` for alternate or scratch directories. Name an alternate working directory in the task packet whenever it changes where the child reads or writes.
- `agent`, `mapreduce`, and `verifier` accept `extensions` and `tools` lists. Omit a list only when intentionally inheriting `workflow.childAgentExtensions` or `workflow.childAgentTools`; missing settings mean all, `[]` means none, and a call-level list overrides its default. A schema-enabled agent keeps terminal `StructuredOutput` even with `tools: []`.
- Tools are an exact allowlist. Naming an extension-owned tool loads its owner but no sibling tools; naming an extension with unrestricted tools exposes built-ins plus all tools from that extension.
- Return a compact status, decision, summary, and artifact paths. Put large results in files. Compact transport never excuses an underspecified task or result contract.
- Use `log(...)` before slow launches and at handoffs. Use `trace(...)` for structured debug state such as selected files, output paths, and compact summaries.
